Section 01 — Demo

Claude Code — AIが「作る」の最前線

ここからはデモパートです。画面を見ながら、AIの「作る力」がどこまで来ているかを体感してください。

Claude Codeは、Anthropic社が提供する開発者向けツールです。
ターミナル（黒い画面）からAIに指示を出すと、AIが自分でファイルを作り、コードを書き、テストし、修正する——人間はやりたいことを日本語で伝えるだけ。

Claude Codeでできること
🌐
Webアプリを丸ごと作る
「営業報告を入力したら自動でグラフ化するアプリ作って」——これだけで、フォーム＋グラフ＋保存機能まで一気に作れる。
📁
複数ファイルを同時に扱える
キャンバスモードは1ファイルだけ。Claude Codeはプロジェクト全体——HTML、CSS、JavaScript、画像、データファイルを一括で管理。
🔄
自分でテスト・修正する
エラーが出たら自分で検知して、自分で直す。人間がエラーを見つけてコピペする手間がなくなる。
🚀
公開まで一気通貫
作ったものをインターネットに公開するところまでAIがやってくれる。メモ帳でHTML保存→ブラウザで開く、のさらに先。
キャンバス vs Claude Code
🎨 キャンバス ⚡ Claude Code
操作 ブラウザ上でチャット ターミナルでコマンド
作れるもの 1ファイルのアプリ・スライド 複数ファイルの本格的なプロジェクト
エラー対応 自分でコピペして伝える AIが自分で検知・修正
向いてる場面 サッと1つ作りたい時 本格的に作り込みたい時
💡
キャンバスは「スケッチブック」、
Claude Codeは「工房」。
まずキャンバスでサッと試作して、手応えがあったらClaude Codeで本格的に作る。
この2段構えが、いちばん効率のいい進め方です。
今日のデモのポイント

今回はデモとして画面を見ていただきます。注目してほしいのは3つ：

1. 指示は日本語。コードを書くのはAI。人間は「何を作りたいか」だけ伝える。

2. エラーが出てもAIが自分で直す。人間がデバッグする必要がない。

3. 出来上がりのスピード。ゼロから動くアプリが何分でできるか、時計を意識してみてください。

Section 02 — Hands-on

キャンバスで「ツール」を作る

前回、Geminiのキャンバスモードでスライドを作りました。
実はキャンバスで作れるのはスライドだけではありません。アプリ、ツール、ダッシュボード、フォーム——HTML/JavaScriptで動くものなら何でも作れます。

今日はスライドから一段上げて、業務で使えるツールを実際に作ってみます。

バイブコーディング — 3つの進め方（復習）
🧱
A. インクリメンタル方式
1つずつ機能を積み上げる。初めて作るものに最適。
📐
B. デザインファースト方式
設計を固めてから一気に作る。完成形が明確なときに。
🎨
C. プロトタイプ方式
ざっくり作って、触りながら育てる。イメージがふわっとしているときに。

キャンバスでアプリを作るときのポイント

ポイント 1 — 「キャンバス＋プロモード」が必須

ツールをキャンバスに切り替えて、モードをプロにする。
高速モードだとコードの質が低く、動かないものが出てきやすい。
「作る」ときは必ずプロモード。これはSession 02から変わりません。

ポイント 2 — 最初のプロンプトに「全体像」を入れる
以下の仕様でWebツールを作ってください。キャンバスモードで。

【目的】営業日報を入力すると、報告メールの文面を自動生成する
【入力項目】日付、来客数、売上金額、特記事項（自由記述）
【出力】Gmailにコピペできるメール文面（件名＋本文）
【デザイン】シンプルで見やすく。スマホでも使えるレスポンシブ対応
【追加機能】入力内容をクリアするリセットボタン

💡 「何を・なぜ・どんな形で」を最初に全部伝える。追加注文が多いと、途中で構造が崩れやすい。
最初のプロンプトに全体像を入れておくのが、キャンバスで精度を上げるコツです。

ポイント 3 — 出来上がったらHTML保存

前回学んだ通り、キャンバスで作ったコードはメモ帳にコピー → .html で保存すると、ブラウザで動くツールになります。
同僚に渡すこともできるし、スマホでも使えます。

保存の手順：キャンバス上のコードを全選択 → コピー → メモ帳に貼り付け → 「ファイル」→「名前を付けて保存」→ ファイルの種類を「すべてのファイル」→ ファイル名を「日報ツール.html」のように「.html」で終わる名前にする。

うまくいかない時のTips（Session 02の復習）

エラーが出たら → そのまま貼る。「動きません」だけだとAIは原因がわからない。

見た目が違う → スクショを撮って貼る。赤丸や矢印を描き込むとなお良い。

チャットが長くなったら → 引き継ぎ書を作って新しいチャットへ。前回学んだ引き継ぎプロンプトを使う。

Section 03

業務棚卸し → AI化の優先順位を決める

業務棚卸しで挙げてもらった候補を、一緒に見ながら「どれから手をつけるか」を決めます。

全部をいきなりAI化する必要はありません。
効果が大きくて、始めやすいものから1つずつ。
判断基準はシンプルに3つです。

優先順位の判断基準
頻
頻度 — どれくらいの頻度で発生する？
毎日やることほどAI化の効果は大きい。月1回しかやらないことは後回しでOK。
手
手間 — 1回あたりどれくらい時間がかかる？
5分で終わるものより、30分かかるものの方がAI化の恩恵が大きい。
適
AI適性 — AIが得意な作業か？
文章の生成・要約・整理・変換はAIの得意領域。
対面の判断や感情を読む作業はAIに向かない。
Session 02で学んだ「得意・不得意」を思い出してください。

たとえば、こんな業務が候補になります。

チーフ業務の中でAI化しやすいもの
📧
営業日報・報告メール
頻度：毎日 ／ 手間：中 ／ AI適性：◎

定型フォームに数字を入れるだけでメール文面が生成されるツールを作れば、毎日の報告が数分で終わる。前ページのプロンプト例がそのまま使える。

🤖
店舗ルール・クレーム対応チャットボット
頻度：随時 ／ 手間：大（電話対応含む） ／ AI適性：◎

Session 02で学んだGemsを使って作成。マニュアルを知識ベースとして読み込ませれば、スタッフがいつでも確認できる「先輩AI」になる。休日の電話対応も減らせる。

🎨
POP・チラシの作成
頻度：週1〜2回 ／ 手間：大 ／ AI適性：○（画像生成）

ChatGPTのGPT Image機能を使えば、テキストで指示するだけで販促用の画像が作れる。既にCanvaを使っているなら、素材生成のスピードが大幅に上がる。

🎙️
営業ロープレ・接客トレーニング
頻度：月数回 ／ 手間：大 ／ AI適性：○（ロールプレイ）

AIに「クレーム客役をやって」「初めてメガネを買いに来た20代のお客さん役をやって」と頼めば、いつでも練習相手になる。チーフとして新人教育にも応用できる。

判断のコツ

「3つ全部高い」ものが最優先。
頻度が高くて、手間がかかって、AIが得意——この3拍子が揃っている業務から始める。

迷ったら「毎日やること」を選ぶ。
AI化の効果は「回数×節約時間」で決まる。月1回30分の作業より、毎日5分の作業をAI化した方が結果的に大きい。

完璧を目指さない。
最初から100点のツールを作ろうとすると動けなくなる。「60点のものを作って、使いながら改良する」が正解。

一緒に作ろう

ここからはOJTパートです。

今日のOJT — 選択肢

優先順位を踏まえて、今日取り組むお題を一緒に決めましょう。

A
チャットボットの仕上げ
宿題で作ったGemを一緒にレビュー → 改善
指示文の精度を上げる。知識ベースをJSON/マークダウンに変換する。テスト質問を投げて精度確認。
B
営業日報ツールの制作
キャンバスモードで日報テンプレートアプリを作る
入力フォーム → メール文面の自動生成 → コピペで送信。毎日の報告がラクになる。
C
POP・チラシの画像生成
GPT Imageで販促素材を作ってみる
テキストで指示 → 画像生成 → Canvaで仕上げ。店頭POPや外活動チラシの素材をAIで作る体験。
D
棚卸しから出た最優先タスク
業務棚卸しで見つかったものを、今日着手
「これが1番効果大きそう」と決まったタスクを、その場で一緒に作り始める。
次回に向けて

今日作ったものを土台に、次回以降さらに磨いていきます。

今日作ったものを実際に使ってみる — 日報ツールなら明日から実際に使う。チャットボットなら同僚に試してもらう。使って初めて改善点が見えてきます。
「ここを直したい」をメモしておく — 使っていて気になったところをスクショ＋メモで残しておくと、次回すぐ改善に着手できます。
毎日AIに話しかける — 仕事に限らず、ちょっとした疑問でもOK。「使う頻度」が上達の最大の鍵です。
余裕があればもう1つ作ってみる — 今日のOJTで「意外と作れる」感覚を掴んだら、別のツールにも挑戦してみてください。
